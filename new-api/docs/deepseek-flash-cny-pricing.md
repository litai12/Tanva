# DeepSeek Flash 人民币 token 定价

本次 token 计价只覆盖 `deepseek-v4.1-flash`、`deepseek-flash`、`deepseek-v4-flash`。其他模型单价、渠道、账号、密钥和分组倍率不调整；Tanva 专用实例的全站人民币显示及 1:1 充值约定见下文。

[DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为每百万 token：峰时普通输入 2 元、缓存输入 0.04 元、输出 8 元；谷时为 1 元、0.02 元、4 元。网关按这些人民币数值记录成本，Tanva 后端再乘 1.5 并按每元 100 积分收费；网关不重复加 1.5，也不乘美元汇率。

生产需要随代码发布更新 `ModelRatio` 三个键为 `1`，`CompletionRatio` 为 `4`，`CacheRatio` 为 `0.02`，并从 `ModelPrice` 移除这三个键。小T facade 回报的 completion token 字段是消耗积分，不是真实 token，因此保留小T原来的固定 `ModelPrice=0.01`，不纳入本次 token 单价/helper/SQL 改动。准备好的 [配置补丁](../patches/2026-10-05/001-deepseek-flash-cny-token-pricing.sql)仅修改这些 JSON 键；没有执行生产写入。代码要求配置匹配，旧美元 `0.15` 或按次配置会在供应商调用前返回明确配置错误。

请求按已有 `RelayInfo.StartTime` 固定峰谷：UTC 周一至周五 `[01:00,04:00)` 与 `[06:00,10:00)` 为峰时，相当于北京时间 09:00–12:00、14:00–18:00；中国节假日全天为谷时。采用[国务院 2026 放假安排](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)，补班周末仍为谷时。低峰把基础倍率减半至 `0.5`，输出与缓存相对倍率保持不变。请求内价格数据供预扣和结算共用，跨时段完成不会重新取当前时刻价格。未知年份报“报价不明”，需要补充官方日历后才能受理相应请求。

Tanva 专用 New API 全站统一外显人民币 `¥`。历史 USD 字段按人民币数字 1:1 使用；余额、模型定价、日志和兼容 billing API 均不做汇率换算。配置补丁 `002-tanva-rmb-display-unit.sql` 设置 `general_setting.quota_display_type=CNY`、`USDExchangeRate=1`、`Price=1`。代码与前端也固定这些显示约定，避免旧缓存或旧配置的 7.3 再次放大人民币数值。保留所有其他模型的价格数字、钱包额度、渠道、密钥、充值分组倍率和优惠。充值基准一元对应一元额度，旧 `Price=7.3` 的美元充值换算停止。

型号列表公布配置的峰值基数，不代表当前请求峰谷报价；实际请求按上述固定时点选价。既有分组倍率由本次补丁保留，部署审核仍应核对 Tanva 使用分组的倍率是否为 `1`。本目录代码与补丁仅针对 Tanva 的 New API 实例，不能应用到另一 TapCanvas 容器。

例如国庆低峰 18,171 普通输入、285 输出：供应商精确人民币成本 `0.019311`；网关整数 quota 按现有规则四舍五入为 `9656`，以每元 `500000` quota 展示为 `¥0.019312`。Tanva 精确值为 `2.89665` 积分，按用户要求最终向上取整消耗 `3` 积分。网关 quota 数量仍按现有整数单位舍入，不用于 Tanva 精确积分结算；后端以供应商 usage 与自己的价格快照计算。

外部支付明确标注“供应商支付金额/价格”：已知真实币种时展示对应币种，未知时展示裸数并注明以供应商支付页或账单为准，不能用 ¥/元标记未知的 Stripe/Creem 实付金额。历史外部交易缺少币种时采用同样规则。订阅的站内 ¥ 价格仅标为“人民币参考价”，并与供应商实际支付币种和金额区分。人民币充值额度与供应商支付金额分别显示，既有供应商商品 ID 和交易金额不改变。

本地验证只调用 Go 纯计价与内存测试，不联系模型、支付或生产数据库。需同步部署代码与配置；此轮未部署。
