# 提示词优化功能说明

本篇说明提示词优化服务、界面与用法，便于结合 AI 工作流提高提示质量。

## 概览

- 服务文件：`src/services/promptOptimizationService.ts`
- UI 演示：`src/pages/PromptOptimizerDemo.tsx`（访问：`/app?prompt-demo`）
- Hook：`src/hooks/usePromptOptimization.ts`
- 默认模型：`gpt-5.6-luna`
- 可选模型：`gpt-5.6-luna`、`gpt-5.6-terra`、`deepseek-v4-flash`

## 服务特性

- 超时策略：单次真实请求最多等待 120 秒，并通过底层 `AbortController` 真正取消；不做前端自动重试，避免旧实现超时后请求仍在后台运行并产生重复调用。
- 规范化输出：强制单段文本、去除多余换行/空白
- 可配置项：`model`、`language`（中文/English）、`focus`、`tone`、`lengthPreference`
- Flow Prompt Optimizer 将模型保存到节点的 `promptOptimizationModel`，标题栏使用原有紧凑胶囊标签，点击标签在浮层中切换模型；积分预览和实际运行读取同一字段，旧节点或非法值回退到 Luna。
- AI Chat 长按提示词扩写按钮打开的助手面板使用同一组三模型，自动扩写沿用面板当前选择。
- 后端只允许三种优化模型，并固定通过 new-api 文本接口执行；客户端旧值（包括 `gpt-5.4`）会在服务端回退到 Luna。网关最后一跳分别映射为 `xiaot-agent-gpt-5-6-luna`、`xiaot-agent-gpt-5-6-terra`、`xiaot-agent-deepseek-v4-flash`，复用小T已经配置好的三大脑渠道。
- 提示词优化器不读取也不发送画布快照。由于最后一跳复用小T facade，每次优化请求必须使用独立临时 `user`、`mode=chat` 和空工具白名单，禁止继承小T会话记忆、画布上下文或代理工具回合。

### 请求/响应

输入：
```ts
type PromptOptimizationRequest = {
  input: string;
  model?: 'gpt-5.6-luna' | 'gpt-5.6-terra' | 'deepseek-v4-flash';
  language?: '中文' | 'English';
  focus?: string;
  tone?: string;
  lengthPreference?: 'concise' | 'balanced' | 'detailed';
};
```

输出：
```ts
type PromptOptimizationResult = {
  optimizedPrompt: string;
  model: string;
  tokenUsage?: number;
};
```

## 使用方法

1) 打开 `/app?prompt-demo` 进入测试台
2) 填写“原始描述”，可选设置语言/语气/重点/长度
3) 点击“生成优化提示”，复制结果到 AI 生成/编辑/融合场景中使用

## 服务配置

- 浏览器不持有模型供应商密钥；请求统一发送到 Tanva 后端，再由 `NEW_API_BASE_URL` / `NEW_API_KEY` 访问 new-api。
- new-api 的 `xiaot-agent` 渠道必须执行 `new-api/patches/2026-08-19/001-xiaot-luna-terra-deepseek-models.sql`，为 `default`、`auto`、`vip`、`svip` 注册三个门面能力；提示词助手不能直接向 new-api 请求没有 ability 的裸 Luna/Terra/DeepSeek ID。

## 最佳实践

- 输出语言与目标一致：中文内容优先中文输出
- 需求不充分时补足背景但不偏题
- 针对融合/编辑任务，在优化后的提示中保留明确操作指令
