# Codex 交互对齐清单

> 基线日期：2026-08-21  
> 对照对象：本机当前 Codex 桌面运行时及其项目、会话、侧栏、线程工具面行为。  
> 产品原则：对齐信息架构和交互状态机，保留 Tanva 品牌、小T能力、Work/Chat 语义和插件合同；不复制 Codex 的代码工作树、Git 审查等不适用于 Tanva 创作场景的业务概念。

## 2. 有意采用 Tanva 语义，不照搬 Codex

| Codex 概念 | Tanva 对应设计 | 原因 |
|---|---|---|
| 本地仓库 / Worktree | Work 项目 + 画布项目上下文 | Tanva 的事实源是项目、素材与工作流，不是 Git 工作树 |
| Browser panel | `tanva.canvas` 工具面 | 画布是小T的基本能力，也是后续多创作插件中的一个 |
| Code review / diff | 文件工作台与产物审阅 | PPT、Excel、图片、视频的可视交付比代码 diff 更符合创作任务 |
| Open side chat | Chat 独立会话 | 当前不引入临时分叉会话，避免与用户明确要求的 Work/Chat 双归属冲突 |
| Copy app link / session ID | 暂不外显 | 当前没有稳定跨设备深链合同，先不放无效入口 |

## 3. 后续版本，不阻塞本轮 1:1 主流程

这些项目需要平台能力或正式发行基础设施，不能仅靠界面伪装成已完成：

- 第三方插件商店、签名、完整性校验、权限审计与撤销；
- Capability Host 独立 Utility Process、CPU/内存配额和崩溃恢复；
- macOS/Windows 正式签名、公证、自动更新与回滚；
- SketchUp、Rhino、Grasshopper、AutoCAD、Photoshop 桥接器的签名随包分发；
- 跨设备任务深链和协作分享。

## 4. 自动验收

桌面回归必须至少执行：

```bash
cd frontend
npx tsc -b --pretty false
npm run test:desktop-plugins
npm run verify:desktop-shell
npm run pack:desktop
# 启动打包应用并开放 9333 调试端口后
npm run verify:desktop-packaged
```

浏览器验收覆盖：项目内新会话、拖入/拖回、Work/项目/Chat 折叠、项目与会话菜单失焦、会话管理菜单、`⌘K`、`⌘B`、画布工具面、PPT 逐页预览、Excel/XLSX、连接器工具面。真实 `Tanva.app` 已进一步通过 `file://` 资源加载、登录恢复、项目内新会话、侧栏显隐和临时会话清理验收。

真实应用验收：先启动打包后的 `Tanva.app` 并开放本地调试端口，再运行 `npm run verify:desktop-packaged`。脚本会验证 `file://` Renderer、加密登录恢复、项目内直接发起会话、画布按钮单行、手动隐藏优先级、`⌘B` 侧栏显隐，并自动删除验收期间创建的临时会话。
