# Tanva — 技术约定（SSOT）

## 目标
- 让新同学能在 30 分钟内跑起来前后端，并理解核心模块边界。
- 对代码现实进行记录：当知识库与代码冲突时，以代码为准并同步回知识库。

## 技术栈
- 前端：React 19 + TypeScript + Vite + Tailwind（含 Radix UI 组件）
- 桌面端：Electron 43 + electron-builder；Codex 式任务外壳，工具面通过内置插件 registry 接入。任务分 `Chat / Work`：Chat 无项目/画布，Work 绑定一个项目；拖入项目或拖回 Chat 是改变归属的直接操作。`WORK` 标题右侧 `+` 只创建项目；每个项目行常驻的 `+` 直接创建并切换到已绑定该项目的新任务，项目行本身只展开/收起目录。Work、Chat 与每个项目目录都可折叠；项目支持置顶/重命名/删除，会话支持置顶/重命名/移动/归档/恢复/删除。拖入或从项目发起任务必须自动展开 Work 和目标项目，项目切换不得重建或隐藏桌面任务。桌面端禁止在加载项目、切换 Work 或删除最后一个项目时自动补建“未命名项目”。删除项目会把已绑定任务迁回 Chat，目录折叠、置顶、归档、侧栏显隐/宽度与任务绑定均本地持久化。所有菜单/弹层必须支持点击外部、窗口失焦和 Escape 关闭，且同层菜单互斥；`⌘K` 搜索支持上下选择和回车打开，`⌘B` 显隐侧栏，`⌘N` 新建 Chat 会话。当前任务顶栏的单一“画布/隐藏”开关必须保持单行，并与小T自动唤起共用 `tanva.canvas` 实例；用户手动隐藏后，本轮后续画布补丁不得自动顶开，下一条用户指令再恢复自动唤起。新建 PPT 与 Excel 必须分别由小T加载 `pptx-generator` / `minimax-xlsx` Skill，按用户真实内容生成并校验原生 `.pptx` / `.xlsx`，再通过 `present_file` 交给 `tanva.artifacts`；消息卡与文件工作台都提供原文件直接下载，禁止固定三页 HTML 模板、模拟表格或文字说明冒充文件。只有维护画布中已有的 HTML 演示节点时才使用 `edit_presentation`；普通文档导出 Markdown。Electron 聊天图片点击统一激活 `tanva.media-preview` 右侧工具面，不打开全屏模态框、不隐藏任务线程，并支持下载和多图切换。消息复制通过 Electron 主进程系统剪贴板完成并显示成功/失败反馈，禁止静默无响应。左下角是账号、个人/团队、余额与切换的唯一入口。Electron 登录令牌必须通过 `safeStorage` 写入系统加密存储，渲染器只保留运行期内存副本；启动时先恢复令牌和本地用户，再后台续期。服务端 refresh 必须匹配当前设备实际提交的 token 并只轮换/退出这一会话，禁止用“账号最新 token”让其他设备顶掉桌面。插件内 Canvas 必须使用 `embeddedDesktop`，隐藏网页项目头、账号/积分导航和第二套小T，并把画布 fixed 浮层约束在插件容器内；React Flow 节点 MiniMap 是画布基础导航，在低细节、拖动、缩放和大图交互期间都必须保持可见。Vite 桌面构建使用 `VITE_DESKTOP_BUILD=1` 与相对 public asset URL，禁止把 `/Logo.svg` 等网站根路径带进 `file://` 安装包。
- 桌面端媒体/线路补充：Electron 聊天图片使用 `128px` 紧凑缩略图，点击仍进入 `tanva.media-preview` 右侧工具面。Electron 隐藏网页 FloatingHeader 时，生图线路切换在画布工具栏保留为唯一入口。小T同一回合同时返回旧版直接生图工具与画布生成节点时，以画布生成节点作为唯一执行链路；只有没有可执行画布生图节点时才回退直接生图，禁止双重扣费和重复媒体卡。
- 桌面端退出合同：Tanva 不作托盘/后台常驻应用；用户关闭主窗口、触发窗口关闭 IPC 或执行系统退出时，都必须有界地清理本机连接器后结束 Electron 主进程，macOS 不得仅关窗口却继续留在 Dock/后台。网页端继续使用 `beforeunload` 保护离站风险；Electron 依赖项目自动保存并由 Main 明确放行退出，禁止浏览器式提示变成不可见的 macOS sheet 后留下无窗口进程。
- 后端：NestJS（Fastify adapter）+ Prisma + PostgreSQL
- AI/多媒体：`@google/genai` / `@google/generative-ai`、图片处理（background removal）、视频/帧等相关能力

## 仓库结构
- `frontend/`：前端应用（Vite）
- `backend/`：后端服务（NestJS）
- `frontend/docs/`：项目文档（大量中文文档）
- `ai-metadata/`：代码索引（imports/exports/依赖图/特征描述）
- `helloagents/`：本知识库（SSOT）

## 开发约定
### Node / 包管理
- Node.js：建议 `>= 18`
- 包管理：项目内主要使用 `npm`（`frontend/`、`backend/` 各自有 `package.json`）

### 常用命令
- 前端开发：`cd frontend && npm i && npm run dev`
- 前端检查：`cd frontend && npm run lint && npm run build`
- 桌面端开发：`cd frontend && npm run dev:desktop`
- 桌面端验证/目录包：`cd frontend && npm run verify:desktop && npm run verify:desktop-shell && npm run pack:desktop`
- 后端开发：`cd backend && npm i && npm run dev`
- 后端构建：`cd backend && npm run build`

### 资源访问
- 直连 OSS/CDN：默认禁用 `/api/assets/proxy`，使用 `VITE_ASSET_PUBLIC_BASE_URL` 将 `projects/...` 等 key 拼成可访问 URL
- 如需重新启用代理：设置 `VITE_PROXY_ASSETS=true`
- 导演台内置模型、纹理与地形只发布到 TOS 的 `director-assets/v1/`，不再随 `frontend/public/` 打包；运行时优先通过 `VITE_ASSET_PUBLIC_BASE_URL` 直连，未配置时使用已部署的广州 TOS 公共基址，不允许回退到本地副本。重新发布时在仓库外准备保持 glTF 相对依赖结构的目录，再运行 `cd backend && DIRECTOR_ASSET_SOURCE_DIR=/absolute/staging/path npm run upload:director-assets`。
- 导演台全景环境统一使用 `scene.skybox / skyboxYaw / skyboxPitch`。`skyboxPitch` 是 -45°..45° 的地平线校准，用于把背景中的地面起点与三维网格消失线对齐；环境球必须在每次渲染前跟随该次真实 render camera，因此导演视口、机位预览和离屏截图消费同一空间基准。约 2:1 图片按等距全景解释，其他横图只做环幕适配，不得宣称其具备可碰撞或可测量的真实地面几何。

### API 前缀与文档
- 后端全局前缀：`/api`
- Swagger：`/api/docs`

### 设计 JSON（强约束）
- `Project.contentJson` / `PublicTemplate.templateData` 只允许保存远程 URL/路径引用；禁止 `data:`/`blob:`/base64 图片等内联内容进入 DB/OSS。
- UI 渲染（画板/图层/缩略图等）：避免直接用 `data:image/*`/裸 base64 做渲染；优先转为 `blob:`（objectURL）或走 `canvas`（参考 `frontend/src/components/ui/SmartImage.tsx`、`frontend/src/hooks/useNonBase64ImageSrc.ts`）。
- Canvas/Flow 正式图片资产必须先完成托管上传并取得远程 URL，再创建节点或图元；上传失败时阻止创建，不得以 `data:`、`blob:`、裸 base64 或未托管外链作为正式资产兜底。裁剪、蒙版、画笔等组件内部可短暂使用 Blob/object URL 预览，但保存、替换正式资产或提交 AI 生成前必须上传。
- AI 图片生成、编辑、融合及同步图像识别的输入边界只接受远程 HTTP(S) URL：前端统一上传，后端 Controller 与 BullMQ 入队前再次校验，`NewApiProvider` 发送 `image_urls` / `image_url` 前最终校验。图像识别统一使用 Gemini/ToAPIs，包含小T大脑选择 `gpt-5.6-luna` 的场景；任何图片识别链路均不得下载图片或转换、透传 base64。视频理解是独立例外：设计数据仍只保存远程视频 URL；豆包 Seed 2.0 视频分析通过 new-api Responses `input_video.video_url` 直接传远程 URL，不下载或转码；Gemini 路径可在后端最后一跳将不超过 15MB 的视频临时编码为 `file.file_data=data:video/*;base64,...`，且不得写入 DB、OSS、Redis 或任务持久化字段，更大视频保留抽帧远程 URL 兜底。

### Flow / AI 运行约定
- Flow 动态画布根节点及其挂到 `document.body` 的交互浮层必须同时标记 `translate="no"` 与 `notranslate`。浏览器网页翻译会包裹/替换 React 管理的文本节点，随后编辑 Prompt 可能触发 `removeChild` / `insertBefore` DOM 不一致；应用内中英文切换继续通过 i18n 完成。自定义 Flow 节点必须经过节点级错误边界注册，单节点渲染失败不得卸载整张工作流。
- 异步视频查询成功后，第三方临时视频必须由后端按逐跳域名白名单下载并转存到 Tanva OSS，再把自有远程 URL 返回前端；不得把需要第三方 CORS 的原始 URL 交给浏览器下载。前端识别到已托管资产时直接复用，不重复下载上传。
- 画布运行价以认证后的 `POST /api/credits/preview` 为唯一报价入口，并与实际预扣复用 `CreditsService.resolveEffectiveCreditsQuote`；前端静态值只允许作为报价返回前的短暂兜底，模型/线路/质量/分辨率/时长等参数必须与真实执行请求一致。Banana 当前只开放普通 `normal/apimart` 与尊享 `stable/tencent` 两条线路；极速 `ultra/beqlee` 入口暂停开放，历史前端偏好和新图片请求统一归一为普通线路，后端只保留旧任务兼容解析。图片积分使用 Tanvas 1.5 倍积分定价：普通 Fast=`20`、Pro(1K/2K/4K)=`60/70/85`、Nano Banana 2(0.5K/1K/2K/4K)=`40/40/50/70`；尊享 Fast=`40`、Pro=`130/130/240`、Nano Banana 2=`45/65/100/155`。GPT Image 2 的 `quality` 与 `resolution` 是独立维度：普通 1K/2K/4K=`20/30/40`；腾讯尊享 `auto` 归一为 `low`，Low=`30/40/50`、Medium=`60/120/190`、High=`230/460/760`，且只由 `quality` 选择 `image2_low/medium/high`，`resolution` 只写入输出配置，不得提升质量档；尊享模式还需在基础质量/分辨率价格上按实际参考图数量追加 `10 积分/张（0.1 元/张）`，preview、同步预扣和异步预扣必须使用同一参考图数量。同步与异步生图入口都必须完整透传 `quality/background/moderation/outputFormat/outputCompression/maskUrl/officialFallback`。
- Flow 节点挂载时的 `POST /api/credits/preview` 必须经过前端共享请求池：请求体完全相同的报价共用同一 in-flight Promise，并短时复用成功结果；不同报价执行全局并发上限，失败结果不得缓存。该优化只合并网络请求，不能改变后端作为唯一报价源或省略任何模型/线路/规格参数。
- AI Chat 固定使用小T单轨入口，不再提供小T开关；preferences v5 会忽略历史关闭偏好并固定开启。旧能力必须作为小T宿主工具接入，不能以关闭小T回到旧链路。
- 小T是 AI Chat 的单一入口；原生“只出图”和“案例搜索”作为 `host_tool` 宿主能力暴露给小T，由小T判断并调用。Tanva 在当前小T消息内执行旧链路并展示图片或案例卡片，不得在进入小T之前做前端分流，也不得要求用户切换回旧聊天模式。小T通过 `flow_patch` 新增具有单一图片/视频资产输出的可执行节点时，`addNode` 只代表工作流结构落地，不构成交付；节点默认必须收到一次 `runNode`，若上游漏发则宿主在本批次所有新增/连线之后确定性补齐，并继续等待远程资产 URL 验收。只有用户明确要求只搭工作流、暂不执行时，生成节点才允许声明 `data.deferExecution=true`；宿主不得通过关键词猜测这一状态，也不得把仍显示“等待生成”的节点判为任务完成。多输出形态的节点由小T显式运行，禁止宿主猜测交付种类。
- 小T单轨仍保留图片比例、图片尺寸、视频比例、视频时长和附件上传入口；四项生成规格作为结构化偏好随每轮 capability manifest 交给小T，用户当轮明确指定的规格优先于已保存偏好。
- 小T的大脑档位、图片/视频模型、图片/视频规格、输出数量与风格锚定统一收口到输入区的“设置”弹窗；不再分别展示模型下拉和画幅/尺寸小按钮，底层偏好字段与持久化行为保持不变。
- 小T请求的内容安全与敏感话题判断由小T facade 渠道自身负责；可选大脑仅为 `xiaot-agent-gpt-5-6-luna`、`xiaot-agent-gpt-5-6-terra` 和 `xiaot-agent-deepseek-v4-flash`，用户外显分别为 `小T-5.6 Luna`、`小T-5.6 Terra`、`小T-DeepSeek V4 Flash`，默认与旧/非法偏好统一回退 Luna。Tanva 不得把完整画布和完整能力说明无条件注入每轮：首轮只发送节点计数/类型摘要、当前选中节点和由请求明确命中的最多 8 个节点，能力清单只保留执行结构；内联/超长内容必须剔除。纯“你好/Hi”等问候以及 Electron 中精确匹配的“打开/收起画布”宿主命令允许本地快路径，即时完成、不调用上游、不扣小T对话积分；其余内容安全与生成判断仍交给 facade，不新增本地安全 Guard。TapCanvas 在已输出 `flow_patch` 后返回的 `xiaot_turn_suspended`，其原因可能是 `host_execution_required` 或 `root_physical_execution_budget_exhausted`，两者都是宿主执行交接而不是失败；Tanva 必须继续执行 patch 并以节点/资产证据裁决终态。
- 小T 自身的每个完整成功对话回合固定扣 `2` 积分，所有可选大脑同价；上游 `usage.total_tokens` 只作运营审计，不参与 Tanva 对话扣费。小T 触发的生图、视频、识图及其他宿主任务仍走各自现有计费链路，与这 `2` 积分分开记账。
- 普通 AI Chat 的纯生图对话统一经小T执行：手动“生成”模式直接进入 `runXiaotAgent`；Auto 模式可沿用工具选择识别生图意图，但命中 `generateImage` 后必须停止旧的前端直调生图流程，把既有用户消息/AI 占位消息交给小T复用。小T使用当前所选 `xiaotModel` 大脑整理提示词，并依图片优选/用户点名选择 GPT Image、Banana 或其他图片节点，完成 `textPrompt → image node → runNode`。
- 非小T且无需联网的 AI 文本能力统一经 new-api `POST /v1/chat/completions`；用户显式开启联网时固定经 `POST /v1/responses` 使用 `web_search`，工具失败必须显式返回，禁止删除搜索后静默重试。普通文字对话、Flow Text Chat、工具选择与 PDF 文本分析默认 `gpt-5.4`；HTML PPT、Paper.js、图像转矢量和普通 Agent 规划/研究默认 `gpt-5.6-luna`。前端不得按“参考/案例”等文本关键词自动开启联网，带真实图片附件的请求必须优先保留在图片生成、编辑或融合链路。提示词优化是独立三模型入口，仅允许 `gpt-5.6-luna`、`gpt-5.6-terra`、`deepseek-v4-flash`，默认 Luna；Flow Prompt Optimizer 将选择持久化到节点，AI Chat 扩写面板与自动扩写复用面板选择，后端按 `billingTag=prompt_optimize` 再次白名单归一并强制走 new-api。所有面向用户的对应型号标签统一使用“小T”品牌前缀，不得外显 `GPT-*`。Image Chat/图片理解恢复 Gemini 多模态三档：Fast=`gemini-2.5-flash`、Pro=`gemini-3.5-flash`、Ultra=`gemini-3.1-pro`，统一由 `/api/ai/analyze-image` 执行。Flow 视频分析使用节点内独立模型选择，不继承全局图片模型：默认 `doubao-seed-2-0-lite-260428`，并提供豆包 Mini/Lite/Pro 与 Gemini 2.5 Flash/3.5 Flash/3.1 Pro；豆包模型请求经 new-api `/v1/responses` 的远程 `input_video` 分析，Gemini 保留完整小视频与抽帧兜底。豆包 Seed 2.0 Pro/Lite/Mini 的产品计费均锚定标准付费 Seedance 2.0 480P 单价，当前分别为 `1/3`、`1/10`、`1/20`：以 `1.25 元/秒` 为锚点，即 Pro=`125/3`、Lite=`12.5`、Mini=`6.25` 积分/秒，按后端安全下载并用 `ffprobe` 识别的完整视频时长计算总价后向上取整；浏览器媒体时长只用于运行前预估。Responses token usage 仍保留在内部审计快照，用于核对上游调用，不参与这三个模型的用户侧视频分析扣费。禁止任何豆包模型回退到 `60/90/120` 固定扣费。公开 API 可返回最终积分及按时长模型的计费时长，但不得返回官方成本、倍率、分档单价或 `pricingSnapshot`；完整快照仅保存在服务端供管理员审计。视频分析结果生成标准 Prompt 的分镜表变体，表格/原文双向编辑，允许增删/复制行、新增/重命名/删除动态列和切换镜头/时序列作用域；内部镜头分组不得依赖用户可删除的“镜号”列。表格态必须支持单元格内 `@` 工作流/项目库/个人库资产、已引用资产定位、常驻横向浏览控件与 `Shift + 滚轮` 横移，并支持 `.xlsx` 导入/导出；工作簿使用“分镜表/镜头总览/列设置”三个 Sheet 保留动态列和作用域。小T大脑默认 Luna，另可选 Terra 和 DeepSeek V4 Flash；图片分析必须调用宿主 `analyze_image` 工具复用 Image Chat，不由小T大脑直接猜图。
