## 背景

微信公众号未将服务端出口 IP 加入白名单时，创建登录二维码会在获取 `access_token` 阶段失败。独立登录页的自动创建 effect 在失败后立即再次执行，形成无间隔死循环，并把单次配置错误放大为大量微信接口请求和告警日志。

## 设计

1. 登录页和登录弹窗创建失败后停止自动重试，只允许用户主动刷新。
2. 每次创建尝试后启动 5 秒前端冷却，刷新按钮展示剩余秒数并禁止重复点击。
3. 前端为匿名浏览器持久化随机 visitor ID；服务端优先按该 ID、旧客户端按真实 IP + User-Agent 建立限流身份。
4. 服务端在调用微信接口前，以 Redis `SET NX PX 5000` 原子限制单个身份 5 秒一次；Redis 不可用时退化为进程内锁。
5. 同一后端进程内并发获取微信公众号 access token 时复用同一个 in-flight Promise，避免不同访问者同时穿透缓存。

## 验收标准

- 微信 IP 白名单配置错误时，每次页面打开只发起一次二维码创建请求，不再自动死循环。
- 同一匿名浏览器 5 秒内重复刷新时，前端按钮不可用；绕过前端直调接口时收到 HTTP 429。
- 多实例部署且配置 Redis 时，5 秒限制跨实例生效。
- 并发 access token 获取只产生一个微信 `stable_token` 上游请求。
- 前后端构建、前端 lint 与专项验证通过。
