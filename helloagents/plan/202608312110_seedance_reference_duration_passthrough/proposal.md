# 变更提案：Seedance 参考媒体时长交由上游裁决

## 背景

Tanva 后端原先在 Seedance 2.0/2.5 任务提交前下载参考媒体并校验单条及总时长。MP4 的帧时间戳、音频尾帧或容器封装可能使请求 15 秒的成片被探测为 `15.01s` 或 `15.1s`，从而在请求到达 new-api/Seedance 之前被本地拒绝。

产品决定不在 Tanva 重复维护这组输入媒体时长范围，由实际上游按当前能力裁决。

## 目标

1. Tanva 不再因 Seedance 参考视频或参考音频的单条/总时长范围拒绝请求。
2. 不为绕过本地范围校验而启动 ffmpeg、裁切视频、重编码或生成派生 OSS 文件。
3. 保持参考媒体原始远程 URL 不变并直接交给 new-api/Seedance。
4. 保留素材数量、任务类型、输出时长和计费所需真实视频时长探测等必要约束。

## 边界

- 上游仍可能按自身实时规则拒绝超长参考媒体；Tanva 应展示上游返回的错误。
- 参考视频计费依赖真实输入时长，因此 URL 不可访问或无法探测时长仍不能继续计费和提交。
- 参考音频当前不参与 Seedance 输入视频时长计费，Tanva 不再为时长范围单独下载探测。
