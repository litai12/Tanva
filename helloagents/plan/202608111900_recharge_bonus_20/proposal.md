# 变更提案：积分充值赠送 20% 永久积分

## 元信息

```yaml
类型: 商业规则变更
方案类型: proposal
优先级: P0
状态: 已完成
创建: 2026-08-11
```

## 背景

个人积分充值原先对最高档年卡生效用户提供 `8 折` 支付优惠。新口径取消价格折扣：所有用户均按固定档位原价支付，基础兑换仍为 `1 元 = 100 积分`；普通用户到账 `100%`，仅有效最高档年卡会员和白名单中显式开启“充值到账 120%”的用户额外获赠 `20%` 永久积分。

## 设计

1. 个人充值档位统一为 `25 / 50 / 100 / 500 / 1000 / 5000` 元，删除原 `200` 元档；报价时由服务端判断是否为有效最高档年卡或开启返赠的白名单用户。
2. 创建订单时客户端提交基础积分；服务端校验原价并重新判定资格，在订单 metadata 快照资格来源、基础、赠送和总到账积分，订单 `credits` 保存总到账。
3. 支付成功后基础积分使用原有 recharge lot；赠送积分使用独立永久 gift lot，`expiresAt=null`，不参与衰减、到期清理或会员到期回收。
4. 两个批次和两条 EARN 流水在同一数据库事务中完成；回调、主动查询和补单通过条件 `updateMany(id + status != PAID)` 原子抢占 PAID 状态，只有更新成功的事务可以发放积分。
5. 历史订单没有新 bonus policy snapshot 时全部积分仍视为原充值积分，不追溯加赠。
6. 旧水印白名单升级为统一白名单，可分别配置去水印、最高档年卡功能权益、充值到账 120%；最高年卡权益不创建订阅，禁止进入会员周期积分发放。

## 验收标准

- 所有用户看到相同原价；普通用户 `25 元`最终到账 `2500`，不得生成赠送批次。
- 有效最高档年卡或开启返赠的白名单用户，`25 元`最终到账 `3000`，其中 `500` 为永久 gift lot。
- `5000 元`档普通用户到账 `500000`，符合资格用户到账 `600000`；套餐列表不得再出现 `200` 元档。
- 白名单列表显示已配置权益 Tag，未开启“充值到账 120%”的白名单用户不得获得返赠。
- 旧订单、重复回调和补单不会重复或追溯赠送。
- 前后端构建与充值专项验证通过。
