# 生图提交反馈与停止语义

## 问题与实现

用户反馈点击生图后界面没有进度，容易再次点击。Flow 原有同步锁已能拦截同一挂载实例内的快速重复调用，但 running 状态晚于参考图解析、上传等异步准备工作。另一个漏洞是停止按钮无条件清空前端任务并释放锁，后端已开始的任务无法取消，用户仍能发起第二个付费任务。

单图节点 generate、generatePro、generateRef、viewAngle、nano2、gptImage2 在入口检查通过后立即进入 running，保留旧图片展示并清除上一轮 taskId/taskPhase/error，避免旧任务恢复回执干扰本轮状态。专业节点显示准备并提交中、排队中、生成中的阶段文字。参考图准备异常由外层捕获并显示失败，finally 释放防重锁。

停止仅向后端尝试取消已取得 taskId 的任务，继续保留本地身份、锁和轮询。尚未取得编号时提示正在准备或提交；取消失败继续跟踪原任务；取消成功也等待轮询回传终态后开放下一次运行。按钮文案不再承诺停止后可以立即重新生成。

## 范围与验证

- 本次不更改后端计价、积分账目或跨标签页幂等机制，不涉及四图批量及视频停止行为。
- `npm run test:flow-progress-runtime`：重跑时间戳、即时 running、旧身份清理与旧图片保留。
- `npm run test:flow-image-submission`：执行实际运行/停止回调，验证连续三次触发只提交一次、完成后可重跑、准备异常释放锁、准备中/取消拒绝/取消成功均保留轮询直到终态。测试使用模拟请求，不调用付费服务。
- 发布只需前端；当前修改尚未部署。
- 验证结果：7 项回归通过，前端生产构建通过（存在原有大包提示）。全仓 lint 未通过；本次修改的所有既有文件相对 HEAD 的错误/警告数量均未增加，新回归文件无 lint 问题。
- 项目约定的 `ai-metadata-sync/scripts/sync-repo.mjs` 在本机指定路径缺失，搜索本机 skills 目录也未找到，因此无法运行该同步脚本。
